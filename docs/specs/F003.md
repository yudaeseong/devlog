## 데이터
마이그레이션 `0001_users_sessions.sql`:
- `users(id INTEGER PRIMARY KEY, email TEXT NOT NULL UNIQUE, nickname TEXT NOT NULL UNIQUE, password_hash TEXT NOT NULL, created_at TEXT NOT NULL)`
- `sessions(token_hash TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE, expires_at TEXT NOT NULL, created_at TEXT NOT NULL)`
- 이메일은 trim + 소문자로 정규화해 저장. 닉네임 중복은 대소문자 무시(`nickname TEXT NOT NULL UNIQUE COLLATE NOCASE`).

결정 사항:
- 해싱: `bcryptjs`(이미 설치됨) `hash(password, 10)`. 새 라이브러리 없음. 비밀번호 최대 72바이트 제한(bcrypt 한계)이라 검증에서 72자 초과는 "비밀번호는 72자 이하여야 해요" 로 거절.
- 세션: `crypto.randomBytes(32).toString("hex")` 토큰을 쿠키로, DB 에는 SHA-256 해시(`token_hash`)만 저장. 쿠키 `devlog_session`: httpOnly, sameSite=lax, path=/, secure=production 일 때, 만료 30일(`expires_at` 과 동일). `getCurrentUser()` 는 쿠키 → 해시 → sessions JOIN users, 만료 시 null.
- 중복 처리: INSERT 를 시도하고 UNIQUE 위반을 잡아 어느 컬럼인지(오류 메시지의 `users.email`/`users.nickname`) 구분해 필드 오류로 반환. 사전 SELECT 후 INSERT 방식은 경쟁 상태가 있어 쓰지 않는다. 오류 문구는 위 표 참고.
- 헤더: 별도 클라이언트 상태 없이 서버에서 `getCurrentUser()` 로 렌더링. 성공 시 `redirect("/")`.

## 주의할 점
- 서버 검증이 기준. 클라이언트는 `noValidate` 를 쓰지 않으면 브라우저 기본 검증이 이메일 오류 문구를 가리므로 `<form noValidate>` 로 서버 문구가 보이게 한다. `type="email"` 은 유지.
- 오류 검사 순서와 표시: 필드별 오류를 각 입력 아래에 `aria-describedby` 로 연결, 실패 시 이메일·닉네임 입력값은 유지, 비밀번호는 비우기.
- 비밀번호·해시를 로그/상태에 반환하지 않는다. SQL 은 파라미터 바인딩.
- SiteHeader 가 cookies() 를 쓰면 모든 페이지가 동적 렌더링이 된다(의도된 것). F001/F002 테스트 회귀 확인(헤더 링크 "글쓰기", "로그인" 유지).
- `redirect` 는 try/catch 밖에서 호출한다(내부적으로 예외를 던짐).
- 문서: `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/cookies.md`(async, 서버 액션에서 set), `.../redirect.md`.
