## 주의할 점
- 규약 (`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/not-found.md`): 루트 `app/not-found.tsx` 가 매칭되지 않는 URL 전체를 처리하고 루트 레이아웃 안에서 렌더링된다. `global-not-found`(실험 기능, next.config 플래그 필요)는 쓰지 않는다. 헤더·푸터가 F001 테스트(기준1·3)에서 `/no-such-page` 에 이미 기대되기 때문이다.
- 상태 코드: 미매칭 URL은 404 로 응답된다. 이 버전 문서상 스트리밍 응답은 200 이 될 수 있는 경우가 있으므로(`notFound()` 호출 경로), 미매칭 URL 에서 실제 404 가 나오는지 테스트로 확인한다. 200 이 나오면 임의로 우회하지 말고 문서(`04-functions/not-found.md`, `loading.md` Status Codes)를 다시 확인한다. 추후 `notFound()` 를 쓰는 기능(글 상세 등)이 이 파일을 재사용한다.
- 뷰포트: `body` 는 `min-h-full flex flex-col`, 푸터는 `mt-auto`. 404 본문은 `<main className="mx-auto w-full max-w-3xl flex-1 px-4 py-16">` 처럼 홈과 같은 `flex-1` 패턴을 쓴다. **`min-h-screen`/`h-screen` 을 쓰지 않는다.** 헤더 높이만큼 넘쳐서 푸터가 첫 화면 밖으로 밀린다. 세로 가운데 정렬이 필요하면 `flex-1` main 안에서 `flex flex-col items-center justify-center` 로 한다.
- 문구는 글자 그대로: '페이지를 찾을 수 없어요', '홈으로'. 해요체 보조 안내 문구는 추가해도 되지만 수용 기준 문구와 중복되어 `getByText` 가 둘 이상 매칭되지 않게 한다(strict mode). 제목은 `h1`.
- '홈으로' 링크는 페이지에 하나만 둔다. 헤더의 "Devlog" 링크와 이름이 겹치지 않는다.
- 스타일은 Tailwind 이고 `dark:` 변형을 함께 쓴다 (예: 보조 문구 `text-neutral-600 dark:text-neutral-400`).
- 새 라이브러리 없음.
