# 기능 하나 구현하기

이 절차는 한 세션에 **기능 하나**만 다룬다. 끝나면 멈추고 결과를 보고한다.

## 0. 현황 파악
- `npm run progress` 를 실행한다.
- 기능 ID가 주어졌으면($ARGUMENTS) 그 기능을, 없으면 "다음 구현 후보"의 첫 번째를 고른다.
- 커밋되지 않은 변경이 있으면 이전 세션이 중간에 끝난 것이다. `progress.md` 의 마지막 기록을 읽고, 이어서 할지 `git stash` 할지 판단해 사용자에게 알린다.

## 1. 계획
- **planner** 서브에이전트에게 기능 ID를 주고 `docs/specs/<ID>.md` 를 받는다.
- 명세를 읽고 이상하면 한 번 더 요청한다.

## 2. 테스트 먼저 (빨간불)
- `feature_list.json` 의 `test` 경로에 테스트를 작성한다. 규칙은 `docs/testing.md`.
- describe 제목에 기능 ID를 넣고, 수용 기준마다 최소 하나의 test 를 만든다.
- 실행해서 **실패하는 것을 확인**한다. (구현 전에 통과하면 테스트가 잘못된 것)

## 3. 구현 (초록불)
- 명세의 "변경할 파일"대로 구현한다. `docs/architecture.md`, `docs/conventions.md` 를 따른다.
- Next.js API는 `node_modules/next/dist/docs/` 에서 확인한다.
- 기능 테스트가 통과할 때까지 고친다: `npx playwright test <테스트 파일>`

## 4. 평가
- **evaluator** 서브에이전트에게 기능 ID를 주고 판정을 받는다.
- FAIL 이면 "반드시 고칠 것"과 "테스트 보강 필요"를 반영하고 다시 평가받는다.
- **3번 연속 FAIL 이면 멈춘다.** `progress.md` 에 막힌 지점을 적고 사용자에게 도움을 요청한다.

## 5. 리뷰
- **reviewer** 서브에이전트에게 리뷰를 받고 "반드시 고칠 것"을 반영한다.

## 6. 검증 (완료 기록)
- `npm run verify -- <ID>` 를 실행한다. 타입·린트·단위·E2E·회귀 테스트가 모두 통과해야 완료로 기록된다.
- 실패하면 원인을 고치고 다시 실행한다. **feature_list.json 을 직접 고치지 않는다.**

## 7. 기록과 커밋
- `progress.md` 끝에 아래 형식으로 세션 기록을 추가한다.
- `git add -A` 후 `git commit -m "feat(<ID>): <제목>"`
- 사용자에게 한 문단으로 보고한다: 무엇을 만들었나, 평가·검증 몇 번 만에 통과했나, 하네스가 막은 것이 있었나.

```markdown
## 세션 YYYY-MM-DD · <ID> <제목>
- 결과: 완료 | 중단
- 평가: FAIL n회 → PASS (주요 지적: ...)
- 검증: n회 (실패 단계: ...)
- 하네스 개입: (훅이 막은 행동, 없으면 "없음")
- 다음 세션에 알려줄 것: ...
```

## 하지 말 것
- 한 세션에 기능 여러 개 구현
- 테스트를 약하게 고쳐 통과시키기, `skip`/`only` 사용
- 수용 기준 변경, 관계없는 파일 리팩터링
